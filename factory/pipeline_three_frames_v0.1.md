## 0. 한눈에 — 세 틀과 배선

```
              ┌───────────── 작품정보 루프 (참조 주입 → 프롬프트) ─────────────┐
              │  feedback                                                    │
              ▼                                                              │
     ┌─────────────────┐   발행 +7D(11D)    ┌─────────────────┐   적재    ┌──────────────┐
     │ ① AI 자동 편집   │ ── 성과 join ───▶ │ ② 쇼츠 분석 공장  │ ───────▶ │  예시 뱅크     │
     │    솔루션 (생성)  │                   │  피처→정규화→판단  │          │  (참조 도서관) │
     └─────────────────┘                   └─────────────────┘          └──────────────┘
              ▲                                                            │  ▲
              ┊  수정 루프 (프롬프트/파라미터)                   인출·피처값 ┊  ┊ 인출
              ┊                                                            ▼  ┊
              └┈┈┈┈┈┈┈┈┈┈┈┈[③ 자가개선 파이프라인 — 이번 문서 밖 / seam]┈┈┈┈┈┈┈┘

  ── 실선: 이번 문서 범위        ┈┈ 점선: 자가개선 seam(나중)
```

- **전방 흐름(생성 → 분석 → 뱅크)**: 쇼츠를 만들고, 성과가 붙은 채 분석 공장을 거쳐, 결과가 예시 뱅크에 쌓인다.
- **피드백(뱅크 → 생성)**: 뱅크에서 인출한 참조가 **작품정보 루프**로 생성 프롬프트에 되돌아간다. ← **이번 범위의 유일한 닫힘 배선.**
- **자가개선 seam**: 뱅크 → 자가개선(인출·피처값), 자가개선 → 생성(수정 루프) 두 배선은 자리만 남긴다.

## 1. ① AI 자동 편집 솔루션 (생성)

**한 줄:** 원본 영상을 받아 쇼츠를 만들어 발행하는 **루프의 진입점**이자 **개선 대상**(ai-video 본체).

| | 내용 |
|---|---|
| 입력 | 원본 영상 + 원작 정보 · **(피드백) 예시 뱅크 인출 참조** |
| 처리 | 원본 분석 → 스토리 구성 → 쇼츠 제작 → 발행 |
| 출력 | 발행된 쇼츠 (→ 시간이 지나 성과가 붙으면 ②로) |

**되돌아 들어오는 것 = 작품정보 루프의 참조** (§3.3에서 상술). 핵심은 이게 **지시가 아니라 참조 재료**라는 것 — "이렇게 만들어라"가 아니라 "이 클러스터에선 이런 사례들이 있었다"를 프롬프트에 깔아준다.

> **[자가개선 seam]** 나중에 자가개선이 만든 **수정안**이 여기로 또 들어온다. 레버 종류에 따라 프롬프트 지시로 오거나(생성 단계 레버), 결정론 파이프라인 파라미터로 온다(컷 길이·자막 타이밍 등). 작품정보 루프(참조)와는 **다른 배선**이다.

## 2. ② 쇼츠 분석 공장 (피처 → 정규화 → 판단)

**한 줄:** 성과가 붙어 넘어온 쇼츠를 **피처화 → 채널 정규화 → 성과 점수 판단**까지 한 공장 안에서 처리해 뱅크로 넘긴다.

**대상 게이트:** 발행 후 **+7D 성과가 온전한 "진짜 쇼츠"만**. 게이트는 **`upload_at`(데이터 날짜, 발행 당일부터 존재) 기준**:
```
video_length ≤ 180s                    -- 쇼츠 길이 (롱폼/중간 배제)
AND sum(impressions) > 0               -- 쇼츠 판별 (게시물/이미지슬라이드=노출 0 배제)
AND min(upload_at) ≤ publish_time + 1d -- 발행 초기 데이터 존재 (좌측절단 배제)
AND max(upload_at) ≥ publish_time + 7d -- +7D 커버
```
> ⚠ `created_at`(적재 시각)은 데이터 날짜보다 **~4일 지연**이라 게이트·창 집계에 쓰면 멀쩡한 영상까지 잘린다(실측: created_at 게이트 4,360 vs upload_at 게이트 32,399). 수집 ~4D 지연이라 +7D가 온전히 적재되는 실제 시점은 **발행 +11D쯤**.
> ⚠ **쇼츠 판별**: laeebly youtube_studio는 쇼츠·일반영상·커뮤니티 게시물을 동일 스키마로 섞어 담아 길이만으론 구분 불가. 표본 45/45에서 `impressions=0`=게시물(피드 노출 없음) / `>0`=진짜 쇼츠로 완벽 분리 → 유일한 SQL측 판별자.
> — 2026-07-07 기준 통과 **31,540 / 64,155** (upload_at 32,399 → 길이≤180 31,635 → impressions>0 31,540).

### 2.1 피처값 추출 (요약)

쇼츠를 2트랙으로 피처화해 **`eb_shorts_features` 1행(병합 와이드)** 으로 병합한다. 피처 + 성과(+7D Σdelta) + 통제(covariate) + 정규화·판단을 **한 와이드 테이블**에 담는다(v0.4의 3분리 대체). PK=`shorts_id`(=youtube_studio.content_id). `eb_` 프리픽스는 같은 DB의 ai-improvement 테이블과 충돌 방지.
- **트랙 A (Gemini VLM)**: 9개 버킷 × `{note, tags, salience}` + `ai_features`(고정 스키마). 버킷마다 **JSONB 컬럼**, 자유 tags엔 GIN 인덱스(codification 집계용).
- **트랙 B (결정론)**: ffmpeg·scene-detect·ASR·OCR·메타로 저비용 전수 추출(평면 컬럼).

버킷마다 **역할 태그**가 붙는 게 이 공장의 심장 — 뒤 단계가 전부 여기에 걸린다:

| 역할 | 뜻 | 예시 버킷 | 쓰임 |
|---|---|---|---|
| **LEVER** | ai-video가 *바꿀 수 있는* 것 | hook · build · payoff · subtitle · tts · audio · point_elements | 자가개선 학습 대상 / "갈린 축" 후보 |
| **MIXED** | 일부 레버·일부 관측 | cover_title (ctr) | 썸네일은 랜덤이라 관측 성격 |
| **COVARIATE** | 작품이 정해버려 *못 바꾸는* 것 | content_context(장르·톤) · scene_observation | **통제·조건**(레버 아님) |

> 상세 정의·앵커·예시는 `gemini_extraction_prompt_v0.4.md`. 이 문서는 역할 구분까지만.

### 2.2 정규화 — 채널 파워 제거 (lift)

성과 원지표는 **채널 크기에 오염**돼 있다(대형 채널 10만 = 실패, 소형 채널 10만 = 대박). 그래서 판단 전에 **채널 대비 배수**로 환산한다:

```
lift_views = 영상 +7D 누적조회(Σ 일일 delta) ÷ 채널 기저 조회수
```
> lift는 **카운트 지표(조회수)에만** 적용한다. 시청지속률·참여 같은 **비율 지표는 이미 채널 크기에 덜 민감**해 lift 없이 바로 백분위(§2.3)로 간다.

**정규화에서 반드시 지킬 것 (v0):**
1. **기저 출처 = laeebly 완전 채널 이력** ★교정(2026-07-07). 채널 기저는 우리 적재분(`eb_shorts_features`, 부분집합)이 아니라 **laeebly 원천의 그 채널 모든 쇼츠**에서 낸다. 우리 테이블에 몇 개 적재됐든 무관하게 채널의 진짜 norm을 쓴다("+10D 크롤 = laeebly 축적"과 일관). 대상은 채점 대상(featurize한 것)이고, 분모 pool은 laeebly 완전 이력으로 분리.
2. **쇼츠 전용(길이 필터)** ★교정. 기저 pool·게이트 모두 `video_length ≤ 180s`(SHORTS_MAX_SEC). 롱폼/중간이 기저·뱅크에 섞이면 오염. (실측: +7D 게이트 중 ~2.4%가 >180s/null → 제외)
3. **시점 누수 방지** — 채널 기저는 각 쇼츠 `publish_time` **이전 trailing 창 `[pt−90d, pt)` 만**, 자신 제외. 판단 시점 계산해 **행에 고정**(`channel_baseline_views`).
4. **성숙도 정렬** — 분자·분모 모두 **같은 +7D Σdelta 창**. (기저 pool의 다른 쇼츠도 +7D 성숙분만)
5. **폐기: 클러스터·전체 기저 폴백** ★교정. 채널 trailing 표본이 부족하면 클러스터/전체 중앙값으로 나누던 원래 폴백은 **삭제**했다 — 그건 "다른 그룹 평균 대비"라 lift의 목적(**채널** 파워 제거)을 정면으로 깨고, 백분위 단계에서 정의 다른 lift를 섞는다. laeebly 완전 이력을 쓰므로 대부분 채널 기저가 잡히고, **진짜 신규 채널**(laeebly에도 <5)만 `lift=null`(가짜로 안 채움). `baseline_cascade`: `channel` | null.
6. 결측 지표 ≠ 0(마스크 후 가중치 재분배), **카운트=lift · 비율=백분위 직접**.
7. **생존편향**(저성과 삭제 → 기준선 상향)은 제거 불가 → 방향만 문서화. (`lifecycle_status`로 private/deleted 표시)
> ※ 클러스터/전체 폴백은 **§2.3 백분위 모집단에만** 남는다(거기선 "어떤 또래와 순위 매기나"라 정당). lift 기저와는 다른 곳.

> **나눗셈은 한 번만.** lift(채널 크기 제거)가 유일한 나눗셈이다.

### 2.3 판단 — 복합 성과 점수 (이진 라벨 아님)

단일 조회수가 아니라 **여러 지표를 합친 0~100 점수**로 판단한다:

```
조회수(Σdelta) ─ ÷채널기저 → lift_views ┐  (상대: 채널 대비 배수)
조회수(Σdelta) ─ 절대값 그대로 ──────────┼→ 캐스케이드 모집단 내 백분위(0~100)
시청지속률(kept_watching_rate) ──────────┤        (z-score 아닌 백분위: 쇼츠 heavy-tail에 강건)
참여율((likes+shares+comments)/views) ──┘
   → × 가중치 가중평균 (결측 재분배)   = 성과 점수 (0~100)
   → 고정 컷 (<33 bad · 33~66 mid · ≥66 good) = 라벨   (mid=중간, 인출에서 제외)
```

- **정규화가 두 번, 서로 다른 일**: `lift`(채널 크기 제거, 조회수만) + `백분위`(지표 간 척도 통일). 백분위는 순위라 이중 정규화가 아니다.
- 지표·가중치 v0.3(config, 학습 전 가정): **`lift`(상대) 0.25 · `절대조회` 0.15** · `retention(kept_watching_rate)` 0.4 · `engagement` 0.2. 결측 지표는 빼고 남은 가중치로 재분배.
- ★**조회 = 상대(lift) + 절대 둘 다** (v0.3 교정). lift만 쓰면 대형 채널의 큰 절대 도달(예: 80만이 채널 평균 100만 대비 lift 0.8)이 소형 채널 9만(lift 0.9)보다 낮아져 상식과 어긋난다 → **절대 조회수 백분위를 15% 얹어** 실제 도달 규모를 반영(사용자 결정). 채널 파워를 완전히 지우지 않고 균형.
- **라벨 컷 = 고정 임계**(`LABEL_CUTS`) ★v0.2 교정. 점수가 이미 "이전 대비 백분위 가중합(0~100)"이라 고정 임계로 자른다. (v0.1의 "전체 3분위 컷"은 새 쇼츠마다 커트가 흔들려 폐기.)
- **`score_basis` 태그** ★교정. 웨이브2 지표(kwr·참여)가 2026-06-19 수집이라 그 이전 발행분은 **계속시청이 없다**(게이트 후보의 ~93%). 풀을 나누지 않고 **전부 한 모집단에서 채점하되**, 각 쇼츠에 `full`(계속시청 반영 4지표) / `reach_only`(계속시청 없어 도달·참여만) 태그를 붙인다. 인출(§3.2)에서 `full` 우선. lift·절대조회 백분위는 태그 무관 전체 공유(표본 최대화), 계속시청 백분위만 있는 것끼리.

**두 개의 캐스케이드는 서로 다르다** (혼동 주의):

| 무엇 | 폴백 순서 | 최소 표본 |
|---|---|---|
| **기저**(lift 분모, §2.2) | **채널만 — 폴백 없음.** laeebly 완전 이력에도 채널 표본 <5면 `lift=null` | 5 |
| **백분위 모집단** | **같은 원작**(`identification_code`) → 클러스터 → 전체 | 10 |

→ **둘을 헷갈리지 말 것.** 기저(lift 분모)는 **채널 폴백 없음** — 클러스터·전체 평균으로 나누면 "채널 파워 제거"라는 lift 목적이 깨지므로 §2.2에서 그 폴백을 **폐기**했다. 클러스터·전체 폴백은 **백분위 모집단에만** 남는다(거긴 "어떤 또래와 순위 매기나"라 정당). → "캐스케이드 = 백분위 모집단"은 여전히 성립하되, lift 기저는 그 캐스케이드에 안 탄다.

### 2.3.1 채점 시점 — as-of (백로그 상호 / 신규 이전만) ★v0.2

백분위 모집단의 **"또래"를 언제 기준으로 잡느냐**가 두 국면으로 갈린다:

| 국면 | 대상 | 백분위 모집단 | 채점 |
|---|---|---|---|
| **백로그**(기존 ~3만) | 이미 다 벌어진 과거 | **상호**(전체, 시간필터 없음) | 최초 1회 배치 (`mutual`) |
| **신규**(앞으로 올라올) | 발행 시점에 미래 없음 | **발행 이전(`pt ≤`)만**, 자신 제외 | 건별 1회, 라벨 **고정** (`asof`) |

- **왜 나누나**: 백로그는 회고적 코퍼스라 상호 참조가 더 정보적(초기 쇼츠를 굳이 눈가림할 이유 없음). 신규는 발행 시점에 미래가 존재하지 않으니 **이전만**(인과적, §2.2 기저의 trailing 원칙을 백분위·라벨까지 확장).
- **as-of 필터는 §2.3 캐스케이드의 각 단에 걸린다**: 원작 중 이전 → 클러스터 중 이전 → 전체 중 이전.
- **핵심 효과**: 신규는 한 번 채점되면 라벨 **고정**(미래 쇼츠가 옛 라벨을 안 바꿈) → 매 적재마다 전체 재채점 불필요. 이미 채점분은 저장된 `lift_views` 재사용.
- **lift(정규화①)는 이미 as-of**(발행 이전 trailing). 백로그·신규 모두 동일 — 바뀐 건 백분위(정규화②)의 모집단 시점뿐.
- 운영: ①백로그 적재(`--no-score`) → ②`--score-only --score-mode mutual`(1회) → ③이후 평상시 `asof`(기본, 신규만).

> **[자가개선 seam]** 성과 점수·good/bad 라벨을 **학습 신호**로 얼마나 쓸지(대조 발견 / 예측 학습)는 자가개선 몫이라 미정. 이 공장은 **점수와 라벨을 산출**하는 데까지.

### 2.4 출력

`eb_shorts_features` 1행에 **피처 + 성과(+7D Σdelta) + 통제(covariate) + 정규화·판단**(`channel_baseline_views`·`baseline_cascade`·`lift_views`·`performance_score`·`perf_label`)을 upsert. 정규화·판단 컬럼은 **공장 후단(`factory/scoring.py`)이 채운다**. 채널 L1 정량은 `eb_channels`로 별도 갱신.

## 3. ③ 예시 뱅크 (참조 도서관)

**한 줄:** 단일 파이프라인이 아니라 **루프 전체가 참조하는 저장소**. 정답을 증류하지 않고, **사례를 참조형으로** 보관한다(도서관이지 정답집이 아님).

### 3.1 적재되는 것 — 두 종류의 참조 재료 (grain 다름)

| 재료 | grain | 무엇 | 테이블 |
|---|---|---|---|
| **쇼츠 레코드** | 쇼츠 1개 | 영상 + 작품정보 + 피처값 + 성과 점수 + good/mid/bad | `eb_shorts_features` |
| **채널 분석 데이터** | 채널 1개 | 아래 2층 | `eb_channels` |
| **원작(IP) 레지스트리** | 원작 1편 | 포맷×서사 cluster_id + tone_tags + is_laeebly_licensed (§4.1) | `eb_ip` |

**채널 데이터 = 2층** (채널당 1개, −3D 크롤 케이던스로 갱신):
- **L1 정량**: 구독자 · **기저 조회수 중앙값** · 변동성 · 케이던스 → **§2.2 lift 정규화의 분모**.
- **L2 아티팩트**: 정체성 · 톤 · 타깃 · 대표작 (자유서술 + 태그) → **생성 dossier 참조**.
- 통제표·채널×클러스터 집계 같은 건 **다운스트림 파생 뷰**일 뿐, 원본 아티팩트를 먼저 저장한다.

> 쇼츠 성과에서 **구독자 수는 약한 예측자**(알고리즘이 비구독자에 배달). 그래서 채널 파워의 주 지표는 구독자가 아니라 **기저 조회수 중앙값**이다.

### 3.2 인출(retrieval) 기준 — v0

생성 시 새 원본의 클러스터로 참조를 꺼낸다.

| 손잡이 | v0 |
|---|---|
| **폴백** | 클러스터(포맷×서사) → 없으면 전체. **중간 단 없음** |
| **개수 k** | good 3 · 대조 1쌍 · 탐색 1 (~5개) — 좁게 시작(많으면 mode collapse) |
| **선별** | **규칙 슬롯**: good 슬롯=성과 점수 상위, 대조 슬롯=하위, 탐색 슬롯=`salience`(특이도) 픽. 슬롯 안에서 최신성·관련성 정렬 |
| **필터** | lift 신뢰 하한(최소 조회수 N=캘리브레이션 미정) · 고정컷 good/bad(`perf_label`) · 생존 필터(비공개·삭제 제외) |

`salience`(기본 템플릿 대비 특이도)가 이미 피처에 있어 **탐색 슬롯의 발산 손잡이로 그대로 재사용**된다.

### 3.3 ★ 생성이 예시 뱅크를 참조하는 법 — 작품정보 루프 상세

**이 문서에서 가장 중요한 배선.** 뱅크의 데이터가 어떻게 조합돼 생성 프롬프트로 넘어가는지를 단계로 푼다.

#### 3.3.0 대전제 — 생성 시점엔 아직 쇼츠가 없다

인출은 **쇼츠를 만들기 *전*** 에 일어난다. 그래서 만들 쇼츠의 VLM 피처(§2.1)는 **아직 존재하지 않는다.** 인출 키는 쇼츠 피처가 아니라 **원작 메타 + 타깃 채널**에서만 나온다. 이게 전체 흐름을 결정한다.

#### 3.3.1 1단계 — 인출 키 계산 (원작 메타 → 무엇을 꺼낼지)

| 원작/입력에서 | → 정하는 것 | 용도 |
|---|---|---|
| 포맷 × 서사구조 | `cluster_id` | 인출 클러스터 (매칭 키) |
| 장르 · 톤 | 조건 필터 (COVARIATE) | 클러스터 안에서 좁히기 |
| 타깃 채널 | 채널 dossier 키 + 채널 기저 | dossier 인출 + 성과 점수 해석 |

#### 3.3.2 2단계 — 인출 (무엇을 꺼내나, §3.2 규칙 적용)

- **쇼츠 레코드**: good 3 · 대조 1쌍 · 탐색 1 (필터: 생존·최소조회수·고정컷 라벨). 클러스터가 비면 전체 폴백 — 단 카드에 **출처(cluster/global) 태그**를 붙여 관련성 강도를 표시.
- **채널 dossier**: 타깃 채널 L2 (1:1). 신규 채널이라 dossier가 없으면 → 클러스터 평균 dossier로 대체하거나 생략.

#### 3.3.3 3단계 — 조립 = 투영(projection) + 캐스팅 (핵심)

꺼낸 쇼츠 레코드는 **9버킷 JSONB라 크다.** 통째로 넣지 않는다 — 통째 = 컨텍스트 낭비 + 모델이 내용을 **그대로 복제(mode collapse)**. 두 가지를 한다:

**(a) 투영 — 카드당 필요한 필드만 뽑아 압축**

| 카드에 넣는 것 | 빼는 것 |
|---|---|
| 작품정보(포맷·서사·장르·톤) | ai_features 원수치 대부분 (헤드라인 1~2개만) |
| 성과 점수 **+ 정규화 기준 태그**(①/②/③) | COVARIATE 버킷 상세 (클러스터로 이미 고정) |
| **LEVER 버킷 note 요약** (편집이 한 *기능* 서술) | extraction_meta |
| 대표 tags (salience 상위) | 원본 영상 자체 |

**(b) 대조 쌍의 갈린 축(diff) 계산** — good A와 bad B에서 **버킷/피처 차이가 가장 큰 축**을 뽑아 첨부. 예: `A: hook_semantic_strength 0.8 / B: 0.3, 성과 격차 Δ40`. → "무엇이 둘을 갈랐나"를 명시하되 "B처럼 하지마"가 아님.

**(c) 캐스팅 프레이밍** — 참조는 **기능**으로 제시하고 **재료 복제 금지**를 명시한다. 규칙은 기능/제약층까지, 재료는 소스별 캐스팅.
> 예: "이 클러스터에선 '오프닝 3초 궁금증 유발(기능)'이 성과와 붙었다. 네 원본 소재로 그 *기능*을 구현하되 사례 내용을 베끼지 마라."

#### 3.3.4 4단계 — 최종 프롬프트 페이로드 구조

여러 소스가 하나로 조합돼 넘어간다:

```
GENERATION PROMPT
├─ TASK           새 원본: 포맷·서사·장르·톤·원작 소여  /  타깃 채널
├─ CLUSTER CONTEXT cluster_id(포맷×서사) · 조건(장르·톤) · 채널 DOSSIER(정체성·톤·타깃·대표작)
├─ 참조 사례 ×3    각: {작품정보, 성과점수[정규화기준], LEVER note 요약, 대표 tags}   ← good 슬롯
├─ 대조 쌍  ×1    {A(고성과) 카드, B(저성과) 카드, 갈린 축, Δ성과}
├─ 탐색 사례 ×1    salience↑ 특이 사례 (강제 발산)
└─ [자가개선 seam] 규칙층(experimental→active 승격분) — 나중에 여기 얹힘
```

- 참조 블록은 **few-shot 프레이밍**으로 TASK와 분리해 제시. 캐스팅 지시(복제 금지·기능 이식)를 함께 넣는다.
- **채널 dossier**는 "이 채널 시청자는 이런 결을 본다"는 **캐스팅 대상 조건**으로 작동(성과 사례와 역할이 다름).

#### 3.3.5 조립 예시 (구체 — 예시일 뿐)

새 원본 = *로맨스 톤 드라마 클립*, 타깃 = *중형 채널*이라면:

```
TASK: 포맷=드라마 · 서사=연속서사 · 장르=[로맨스,드라마] · 원작="○○ 8화 고백 씬" / 채널="A드라마클립"
CLUSTER: DRAMA_SERIAL · 조건 tone∋로맨스 · DOSSIER{정체성:감성드라마 편집, 타깃:2030 여성, 대표작:…}
참조1(good, cluster): {로맨스 드라마 / 점수 88[②클러스터] / hook: "정적 깨는 한마디로 궁금증" / tags:[감정정지,대사훅]}
참조2(good, cluster): {휴먼 드라마 / 점수 81[②] / build: "회상 없이 직진 전개로 긴장 유지" / tags:[직진전개]}
참조3(good, global): {단편 / 점수 79[③전체] / payoff: "여운형 미해소 엔딩" / tags:[여운엔딩]}   ← 폴백 출처 표시
대조쌍: A(점수90) vs B(점수35), 갈린 축=hook_semantic_strength(0.85 vs 0.25), Δ55
탐색: {스릴러 / salience 0.9 / "오프닝에 결말 스포로 역행" / tags:[결말선공개]}   ← 클러스터 밖 발산
지시: 위는 참조다. 기능(궁금증 유발·직진 전개)을 네 로맨스 소재로 이식하되 사례 내용 복제 금지.
```

#### 3.3.6 오염 방지 규칙 (요약)

- 점수엔 **정규화 기준(①/②/③)** 태그 → 같은 88점도 ①(같은 원본) 정규화가 ③(전체)보다 신뢰 높음.
- 카드엔 **인출 출처(cluster/global)** 태그 → 폴백으로 온 사례는 관련성 약함을 모델이 알게.
- 대조 쌍의 갈린 축은 **레버 *가설*** 이지 확정 규칙 아님 (확정 규칙은 게이트 통과 후 `[자가개선 seam]`).
- 개수는 좁게(§3.2) — collapse 방지. 탐색 슬롯이 발산을 보장.
- 장르 태그·톤은 클러스터 키가 아니라 **조건(condition)**.

## 4. 관통 개념 (세 틀 공통)

### 4.1 클러스터 = 포맷 × 서사구조 (원자 키)
- 포맷과 서사구조를 **묶은 한 덩어리**가 매칭·비교·인출의 기준. 편집 전략이 실제로 갈리는 축이라서.
- **장르**는 종류가 많아 클러스터로 쓰면 과분할 → **태그**로만.
- **톤**은 멀티라벨이라 키에 넣으면 조합 폭발 → **조건(COVARIATE)** 으로.

**클러스터는 원작(IP) 단위로 부여된다** (`eb_ip` 레지스트리, PK=`ip_key`). classify 스테이지가 두 경로로 분기(둘 다 eb_ip에 쌓임, 캐시로 중복 LLM 방지):
- **라이선스**(`identification_code` 有, ~57.7%): laeebly 코드로 조회 → 없으면 메타로 LLM 분류. `has_source_video=true`.
- **비라이선스**(코드 無, ~42.3%): laeebly가 원작을 안 주니 **VLM이 대신 식별** — `description`(1순위)+영상으로 원작명·포맷·서사·장르 추출 → `ip_key='t:'+정규화제목`으로 등록. 설명란만으로 충분히 확신하면(conf≥임계) **영상 생략(화면이 설명란을 덮어써 오판하는 것 방지)**.
- **자체제작**(원본 영상물 편집이 아님 — 밈·이슈정리·이미지+TTS 논평): `has_source_video=false`, `cluster_id=null`, IP 미등록. 회사 관심대상은 드라마·영화·예능 등 **원본 편집 클립**뿐(자체제작은 대상 아님). 배제 대신 적재+플래그(오판 대비).
- **"같은 원작 = 같은 클러스터"** — 라이선스=코드, 비라이선스=정규화 제목으로 묶어 라벨이 갈리지 않는다. 쇼츠는 원작 cluster_id를 상속.
- ★라이선스 여부(`is_laeebly_licensed`)와 원본편집 여부(`has_source_video`)는 **다른 축**: 비라이선스라도 원작 클립이면 분석 대상.

### 4.2 데이터 타이밍 · 집계
- 대상: **+7D** 성과 창(발행 ~ +7일). 게이트는 `upload_at`(데이터 날짜) 기준(§2). `created_at`(적재시각)은 ~4일 지연 → 온전 적재 시점은 **발행 +11D쯤**.
- 일일 데이터는 **증가분(delta)** → 누적 성과 = **Σ delta**(content_id별 SUM). 스냅샷 최댓값 쓰면 틀림.
- 단 **비율 컬럼**(avg_view_percentage·kept_watching_rate·ctr 등)은 **SUM 불가** → 조회/노출 가중평균으로 재계산. likes/dislikes는 철회로 음수 delta 가능.
- 웨이브2 지표(지속률·좋아요·공유·댓글 등)는 2026-06-19 수집 시작 → 그 이전 발행 영상은 **결측(≠0)**.

### 4.3 정규화 = 교란변수 통제
- **채널 파워**는 lift로 나눠 통제(§2.2). **장르·톤·씬**은 피처 스키마에서 이미 COVARIATE로 분리.
- 목적은 "어느 채널이 크나"가 아니라 **"어떤 편집이 먹히나"** 를 배우는 것.

### 4.4 원칙 (설계 가드레일)
- **참조 도서관이지 정답집이 아니다** — 클러스터에서 "정답" 증류 금지(관측 천장·생존편향).
- **규칙은 기능/제약층까지, 재료는 소스별 캐스팅** — 다양성이 목적함수, 탐색 필수.
- **관측 격차 → 규칙 직행 금지** — 규칙화 전 게이트 통과.

## 5. [자가개선 seam] — 나중에 채울 자리

이번 문서 밖. 연결 지점만 남긴다:

- **뱅크 → 자가개선**: 인출·피처값(특히 LEVER 버킷의 good/bad 대조).
- **자가개선 → 생성**: 수정 루프(프롬프트 지시 또는 결정론 파라미터).
- **미룬 결정**: good/bad 라벨을 학습에 쓰는 강도(§2.3 seam).
- **경로 후보**: `codification` 패스(자유 tags → emergent 레버, ai_features → 회귀 covariate), A/B 검증, experimental → active 승격.

## 6. 결정 상태 · 미해결 숙제

**확정 · 구현됨 (②):** 적재 테이블 `eb_*`(병합 와이드) · 공장 코드 `factory/`(독립 모듈) · 2트랙 추출 · +7D 게이트(upload_at + 길이≤180 + impressions>0 쇼츠판별) · lift 정규화 + 두 캐스케이드 · 복합 성과 점수(0.4/0.4/0.2) · **as-of 채점(백로그 mutual / 신규 asof) + 고정컷 good/mid/bad** · 채널 2층(`eb_channels`) · 원작(IP) 레지스트리(`eb_ip`, 라이선스 유무 `is_laeebly_licensed`).
