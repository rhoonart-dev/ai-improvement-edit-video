# 예시뱅크 → 생성 프롬프트 주입 (ai-video 담당자 참고용)

> **목적**: ai-video 생성 파이프라인을 수정하는 분에게 "예시뱅크가 생성 쪽에 **뭘, 어떤 형태로** 넘겨줄지"를 미리 보여주는 참고 문서. 실제 주입 배선은 **아직 없다**(이 문서가 그 자리를 설계).
> **주의**: 여기 나오는 프롬프트는 **참고용 목업**이다. 실제 ai-video 주입 시엔 형식·토큰·few-shot 개수를 그쪽 파이프라인에 맞춰 다시 다듬어야 한다.

---

## 0. 한 줄 요약

새 원본을 편집할 때, 그 작품의 **클러스터(포맷×서사)** 로 예시뱅크에서 성과 좋았던 쇼츠들을 인출해 **"정답이 아니라 참조 재료"** 로 생성 프롬프트에 깔아준다. (설계문서 `../pipeline_three_frames_v0.1.md` §3.3)

```
새 작품(포맷·서사·장르)  →  매칭 클러스터  →  예시뱅크 인출(4조각)  →  생성 프롬프트  →  [ai-video 생성]
                                                                              ▲ 여기가 아직 안 이어진 seam
```

---

## 1. 무엇이 주입되나 — 4조각 (§3.3)

| # | 조각 | 내용 | 어디서 |
|---|---|---|---|
| ① | **참조 사례 카드**(few-shot) | 그 클러스터 성과 상위 쇼츠들의 훅 서술·태그·감정·컷수·점수 | `eb_shorts_features` (VLM 버킷 + 성과) |
| ② | **대조 쌍**(good vs bad) | 같은 클러스터에서 성과 갈린 두 편 + "갈린 축" | 위 + 피처 비교 |
| ③ | **탐색 슬롯** | 관련성 낮아도 특이한(salience↑) 사례 1개 (강제 발산) | 버킷 `salience` |
| ④ | **채널 dossier** | 타깃 채널 L2 아티팩트(정체성·톤·타깃) | `eb_channels.dossier` *(아직 비어있음)* |

- 전부 **지시가 아니라 참조**다. "이렇게 만들어라"가 아니라 "이 클러스터에선 이런 사례들이 있었다".
- 장르·톤은 클러스터 키가 아니라 **조건(condition)** 으로 곁들인다.

---

## 2. 인출 로직 (`make_report.py`의 `retrieve()`)

```
클러스터 매칭 → 그 클러스터 쇼츠들을 성과순 정렬
  ① good 카드   : VLM 있는 상위 good N개 (없으면 전체 폴백 + [출처] 태그)
  ② 대조 쌍     : good 최상 vs bad 최하 (피처 비교 가능하게 VLM 있는 것 우선)
  ③ 탐색 슬롯   : salience 최고
폴백 캐스케이드: 원작 → 클러스터 → 전체 (표본 부족 시 넓힘, 출처 태그로 관련성 표시)
```

정답 증류 금지(관측 천장·생존편향) — 클러스터는 **검색 키**지 정답 자리가 아니다.

## 3. 실제 출력 예시 (목업)

`《오늘 뭐 먹지? 랜덤 밥상》`(예능×에피소드완결) 가상 작품으로 인출한 프롬프트. **값은 전부 실제 수집 데이터**(예: hook 서술은 SNL 쇼츠의 실제 `hook_0_3s` 버킷).

> ⚠️ **아래 예시의 hook 서술·제목은 리포트 가독성 때문에 `…`로 잘려 있다** (`make_report.py`에서 `note[:70]`, `title[:30]` 등). **실제 생성 프롬프트에 주입할 때는 절대 자르지 말고 전체 값을 넣어야 한다** — note는 3문장 이상의 서술이고, 그게 편집 문법의 핵심 재료다. 잘린 채 주입하면 참조 정보가 손실된다. (`build_prompt`의 `[:N]` slicing은 리포트 전용이니, 주입 코드에선 제거할 것.)

```text
# 쇼츠 생성 브리프 — 《오늘 뭐 먹지? 랜덤 밥상》
[작품정보] 포맷=예능 · 서사구조=에피소드완결 · 정서톤=코믹, 훈훈, 일상 · 장르=예능/리얼리티
[설정] 매 회 랜덤으로 정해진 재료·상황으로 게스트가 즉석 요리 대결을 벌이는 관찰 버라이어티.
[매칭 클러스터] 예능×에피소드완결  (예시뱅크 내 13개 참조)

## ① 참조 사례 카드 (few-shot) — 이 클러스터에서 성과 좋았던 편집들
  · 「고유가 피해지원금에 대한 시민들의 솔직한 생각 #snl」 (점수 96.88, lift 81.98)
      hook: 영상이 시작되자마자 인터뷰어가 '피해지원금 지급'이라는 사회적 이슈를 던지고, 시민 역할의 인물이 시큰둥하고 냉소적인 반응…
      tags: 인터뷰, 냉소적반응, 사회이슈, 빠른문답 | 감정: 유머 | 컷 7개/51.5초
  · 「스타벅스 논란 풍자해버린 SNL」 (점수 89.58, lift 4.91)
      hook: 카페 알바생이 '정청내일모레님, 장동혁거세님'이라는 기상천외한 닉네임을 부른다. 정치인 이름을 교묘하게 비틀어…
      tags: 닉네임, 패러디, 호기심유발, 상황극 | 감정: 유머 | 컷 9개/51.0초
  · 「수영장 비키니 빌런 말로 참교육하는 이수지」 (점수 88.54, lift 38.33)
      hook: 실내 수영장에 파격적인 비키니를 입은 여성이 등장, 기존 회원들이 시선을 집중하며 갈등을 예고…
      tags: 비키니등장, 시선집중, 갈등예고, 호기심유발 | 감정: 유머 | 컷 19개/52.0초

## ② 대조 쌍 (good vs bad) — 같은 클러스터에서 성과가 갈린 두 편
  GOOD 「고유가 피해지원금…」 점수 96.88 / lift 81.98
  BAD  「인생 첫 놀이기구…」 점수 14.25 / lift 0.06
  → 갈린 축: 컷수(7 vs 21) · 길이(51.5 vs 40.5초)
     지시: 'A(good)처럼 컷 리듬을 가져가되, 새 소재로'

## ③ 탐색 슬롯 — 관련성 낮아도 특이한(salience↑) 사례 1개 (강제 발산)
  「스타벅스 논란 풍자…」 salience 0.90 — 기본 템플릿에서 벗어난 시도 참고(다양성 목적)

## ④ 채널 dossier — 타깃 채널 L2 아티팩트
  (eb_channels.dossier 미충전 — 정체성·톤·타깃·대표작은 후속 생성 패스)

## 생성 지시
  위 참조를 '정답'이 아닌 '재료'로 삼아, 새 원본에서 예능×에피소드완결 편집 문법
  (위 good 카드의 훅·컷 리듬·감정 소구)을 변주해 쇼츠 1편의 편집 계획
  (훅 0~3초 / 빌드 / 페이오프 / 자막·TTS)을 제안하라.
```

> 리포트(`report.html`)에는 **예능(참조 풍부)** + **드라마(참조 적어 폴백 시연)** 두 시나리오가 나란히 있어, 캐스케이드 폴백이 어떻게 작동하는지 대비해 볼 수 있다.

## 4. 데이터 출처 (주입에 쓸 컬럼)

| 조각 필드 | eb_shorts_features 컬럼 |
|---|---|
| 훅 서술·태그·salience | `hook_0_3s` (jsonb: note/tags/salience/ai_features) — 그 외 build·payoff·point_elements 등 10버킷 |
| 감정 | `point_elements->ai_features->emotion_category` |
| 컷수·길이·자막밀도 등 | `cut_count` · `duration_sec` · `subtitle_density` … (결정론 트랙) |
| 성과 점수·라벨 | `performance_score` · `perf_label` (good/mid/bad) · `lift_views` |
| 클러스터·원작 | `cluster_id` · `identification_code` / `eb_ip`(원작 레지스트리) |
| 제목 임베딩(선택) | `title_embedding` vector(768) — `--embed` 시 |

버킷 정의는 `../vlm_feature_schema_v0.4.json` / `../gemini_extraction_prompt_v0.4.md`.

## 5. 구현됨 vs ai-video가 할 일

| | 상태 |
|---|---|
| 예시뱅크 적재(피처·성과·클러스터·점수) | ✅ 구현 (`factory/`) |
| 인출 + 프롬프트 텍스트 조립 | ✅ 목업 (`make_report.py`의 `retrieve`/`build_prompt`) |
| **이 프롬프트를 실제 생성에 주입** | ❌ **미구현 — ai-video 쪽 작업 (자가개선 seam)** |
| 채널 dossier(④) 생성 | ❌ 미구현 (`eb_channels.dossier` 별도 패스) |
| 프롬프트를 생성 후 성과로 되먹임(A/B, 수정루프) | ❌ 미구현 (③ 자가개선 파이프라인) |

**ai-video 담당자가 볼 것**: ①~④ 조각의 **형태와 재료**. 실제 주입 시엔 이 텍스트를 그대로 쓰기보다, ai-video 프롬프트 구조(시스템/유저 메시지, few-shot 슬롯, 토큰 예산)에 맞춰 **각 조각을 재배치**하면 된다. 데이터는 `eb_shorts_features`를 클러스터로 조회하면 나온다.

## 7. 러프한 부분(목업 한계)

- ⚠️ **텍스트 잘림**: 리포트 예시는 `note[:70]`·`title[:30]`으로 잘려 있다. **실제 주입 땐 전체 값 사용**(자르지 말 것). `build_prompt`의 `[:N]`은 리포트 전용.
- **"갈린 축"**(②)은 피처값 차이를 규칙으로 뽑은 것 — 진짜 인과가 아니다. 표본 적으면 우연일 수 있음.
- **채널 dossier(④)** 는 아직 placeholder.
- few-shot 개수·정렬·필터(최소 조회수 하한 등)는 v0 손 설정 — 실제 주입 시 캘리브레이션 필요.
- 정답 증류 금지 원칙 유지: 참조는 **재료**, 다양성이 목적함수(탐색 슬롯 필수).
