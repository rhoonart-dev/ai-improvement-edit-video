# judge 평가자 개선용 기준 쌍 (golden pairs)

**사람이 우열을 판단했는데 judge 가 그러지 못한 쌍**을 모은다. 루브릭을 고칠 때
"이 쌍을 제대로 가르는가"가 합격 기준이 된다.

## 왜 이 파일이 필요한가

`review_decisions` 는 **클립 단위 합격/반려**만 담는다. "A가 B보다 낫다"는 **비교 판단**을
담을 자리가 없어서, 검수자들이 실제로 내린 가장 값진 신호(같은 소재를 놓고 어느 구성이 나은지)가
기록되지 않고 사라진다. 이 파일이 그 임시 보관소다 — 쌍이 쌓이면 테이블로 옮긴다.

## 사용 규칙

- ⛔ **성과 판정·승격에 쓰지 않는다** (CLAUDE.md §7). 평가자(judge) 개선 전용이다.
- 새 루브릭 축의 합격 기준은 **"노이즈 폭을 넘는 차이로 사람 선호와 같은 방향"** 이다.
  단순히 "방향이 맞다"는 부족하다 — judge 는 같은 클립 재실행에서도 0.025~0.375
  (중앙값 0.05, 2026-08-06 기준 재실행 9쌍 실측) 흔들린다.
- 쌍은 **같은 소재**여야 한다. 소재가 다르면 구성이 아니라 소재를 비교하게 된다.

| | 선호 ✅ `4f` | 비교 대상 `f8` |
|---|---|---|
| clip_id | `0bee4149…` | `efc9863b…` |
| run_id | `놀라운_토요일_4f` | `놀라운_토요일_f8` |
| 소스 구간 | 422–598초 | 218–596초 (중첩) |
| 길이 | 49.7초 | 48.9초 |
| 발행 | `iYe03Z6IX_8` | `UWzDX5YD3Ws` |
| 제목 | 꼴찌 후보가 1등으로 탈출하자 제대로 깐족대는 김동현 | 바보 취급당하던 김동현 본업 지식으로 1등 탈출 |
| 구성 | 결과 선공개 → 내막 → 보상 (훅=멤버 경악 리액션 12초) | 시간순: 사건 → 추론 → 결과 (훅=몸싸움 4초) |
| 시간 배분 | 12 / 15 / 23초 | 4 / 25 / 20초 |

**사람 판단**: 검수자 **2인 독립 일치로 `4f` 선호**(대시보드 밖 구두 판단 — `review_decisions`
에는 둘 다 `approved` 로만 남아 있다. 결정 자체는 둘 다 합격이고, 우열은 이 기록이 정본).
근거: 훅이 질문("꼴찌가 어떻게 1등을?")을 만들고 build 가 답, payoff 가 보상을 준다.
제목도 `4f` 는 '어떻게'를 남기고 `f8` 은 방법("본업 지식으로")까지 스포일러한다.

**judge 판단**: `f8` 0.85 vs `4f` 0.825.

| 축 | f8 | 4f |
|---|---|---|
| hook_3s | 0.9 | 0.8 |
| visual_hook | 0.9 | 0.8 |
| pacing | 0.8 | **0.9** |
| completion_pull | 0.8 | 0.8 |

**진단**: judge 가 *거꾸로 판단한 것이 아니라 **변별하지 못한 것***이다. 차이 0.025 는
재실행 노이즈(중앙값 0.05)보다 작아, 다시 돌리면 순서가 뒤집힐 수도 있다. 총점은 4축 단순
평균이라 이 차이의 정체는 축 하나가 한 칸 움직인 것뿐이다.

원인 가설(맥2 2026-08-06 분석): 루브릭에 **정보 배치(세그먼트 간 관계)를 보는 축이 없다.**
`hook_3s`·`visual_hook` 은 첫 3초 시각 임팩트만 재서 몸싸움 > 리액션 샷이 되고,
`completion_pull` 은 둘 다 0.8 로 변별에 실패했다. 사람이 본 것은 훅-국소 속성이 아니라
"훅이 만든 약속을 build 가 받고 payoff 가 갚는가"라는 **전역 구성**이다.

**이 쌍의 용도**: 새 축(서사 계약)이 `4f` 를 `f8` 보다 **노이즈 폭 이상**으로 높게 매기는가.
폼 중립성도 함께 본다 — reaction-first 를 기계적으로 우대하면 event-first 가 정답인 소재
(예: 쇼츠션샤인 참교육 0.975)를 낮게 매기는 반대 편향이 새로 생긴다.

## 환각 플래그 불일치 사례 — 같은 run 에서 양방향 오판 (2026-08-06 등재, 맥5)

단일 클립 사례**를 모은다 — 루브릭 v3 의 환각 축 보정 재료. 유미의 세포들 시즌3 EP1,

| clip_id | `f62a490c…` | `46a612d4…` |
| 소스 구간 | 735.5–956.3초 | 326.0–547.5초 |

**진단**:
- `shorts_2`: judge 가 제목·묘사의 사실성 오류를 통과시켰다(거짓음성). 사람은 내용 대조로 환각 판정.
- `shorts_3`: judge 가 "시즌 표기" 같은 **메타데이터 수준 의심을 환각으로 승격**시켰다(거짓양성 —
  사람이 명시적으로 부인). 정작 사람이 잡은 실제 결함은 **제목이 약속한 장면(이어폰 철벽)이

  없어 environment 플래그가 헛돈다.

**이 사례의 용도**: 환각 축 개선안이 ① shorts_2 를 잡고 ② shorts_3 의 시즌 표기를 환각으로
올리지 않으며 ③ '제목이 약속한 장면의 부재'를 별도 신호로 내는가. (제목-장면 계약 검증은
생성 쪽 가드 후보이기도 하다 — SNL 건 백로그와 합쳐 볼 것.)

## 쌍 #2 — 커리어데이 EP3 (2026-08-10 등재, 맥5)

같은 회차·같은 주제이고 **소스 구간 164.7~185.6 을 공유**하는 대조쌍. 소재가 같으니
차이는 순수하게 **어디를 붙였는가**에서 온다.

| | 선호 ✅ `d0` | 비교 대상 `f6` (먼저 발행됨) |
|---|---|---|
| clip_id | `5f320663…` | `25918ea0…` |
| run_id / take | `커리어데이_d0` / shorts_1 | `커리어데이_f6` / shorts_2 |
| 제목 | 일보다 사람이 힘들면 / 이 현실 조언을 들어보세요 | 일보다 사람이 힘들 때 / 30년차 인사가 내린 결론 |
| 길이 | 49.7초 | 49.7초 (동일) |
| 발행 | 미발행(검수 합격) | `kAzOU66b_ZY` |

**컷 구성** (소스 379.5초, 인트로 0~17.5 는 필터가 제외)

| | `d0` (선호) | `f6` |
|---|---|---|
| 1 | hook 164.7–185.6 (20.9초) — "30년 중 제일 힘들었던 건 사람 관계" | hook 17.5–28.4 (11.0초) — **자기소개** "안녕하세요… 인사쟁이 황성현… 오늘은 상담쟁이 역할" |
| 2 | build 197.4–207.8 (10.4초) — "조직문화로 푸는 건 CEO도 못 한다, 현실적으로 접근" | payoff 164.7–203.8 (38.7초) — 같은 공감 + "조직문화로 푼다? **솔직히 어렵다고 보시면 되고요**" |
| 3 | payoff 266.2–284.6 (18.4초) — **실행 조언** "업무 분장이 모호하니 조직장끼리 가지치기를 요청하라 / 우리 일이 맞으면 '내가 할게요'" | — |

**사람 판단**: `d0` 선호. 검수 코멘트 원문 — *"'힘든 상황에 대한 정리와 공감-해결해볼 수 있는
방안 제안' 구조로 완결성이 있음. 이전에 올라간 영상과 중복된 장면이지만 이전 영상은 앞부분이
더 붙어있고 이 영상은 뒷부분이 더 붙어있어서 합격시켜봄."*

근거를 수치로 옮기면 셋이다.
1. **정보 밀도** — `f6` 은 49.7초 중 **11초(22%)가 채널 인사말**이다. 그 11초가 주는 정보는
   "이 사람이 인사 전문가"뿐인데 제목·자막이 이미 말하고 있다. 실질 본문 38.7초 vs 49.7초.
2. **약속의 이행** — `f6` 은 제목이 "**결론**"을 걸어놓고 마지막 대사가 *"솔직히 말씀드리면
   어렵다고 보시면 되고요"* 로 **부정에서 닫힌다**(진단까지만). `d0` 은 같은 "어렵다"를
   중간 전환점으로 쓰고 뒤에 실행 가능한 조언을 붙인다.
3. **막 구조** — `d0` 3막(공감→진단→해법) vs `f6` 2막(인사→공감).

**judge 판단**: `d0` 0.6 vs `f6` 0.575.

| 축 | f6 | d0 |
|---|---|---|
| hook_3s | 0.6 | 0.7 |
| visual_hook | 0.2 | 0.2 |
| pacing | 0.7 | 0.8 |
| completion_pull | **0.8** | **0.7** ← 역전 |

**진단**: 총점 차이 0.025 는 재실행 노이즈(중앙값 0.05)보다 작아 **변별 실패**다(쌍 #1 과 동일).
더 나쁜 신호는 `completion_pull` 이 **거꾸로** 갔다는 것 — "끝까지 보게 하는가"를 보는 축이
해법 없이 끝나는 쪽을 높게 줬다. 네 축이 전부 국소 속성(첫 3초·시각 임팩트·템포)이라
"**약속한 것을 갚는가 / 정보가 완결되는가**"를 볼 자리가 없다.

**쌍 #1 과의 관계**: #1 은 *정보 배치*(훅이 만든 질문을 build 가 받는가)를 요구했고,
이 쌍은 *정보 완결*(제목이 건 약속을 payoff 가 갚는가 · 본문 아닌 구간이 얼마나 차지하는가)을
요구한다. 서로 다른 결핍이므로 **새 축은 둘을 함께 가르는지**로 검증한다.

**이 쌍의 용도**: 새 축이 `d0` 를 `f6` 보다 노이즈 폭 이상으로 높게 매기는가. 그리고
`completion_pull` 의 역전이 해소되는가.

**부수 관찰 — 생성 쪽 단서 2건** (평가자 개선과 별개, 백로그 후보)
- `f6` 의 인사말 구간은 인트로 필터(0~17.5)가 **정상 동작한 바로 다음 구간**이고, Gemini 가
  정식 후보로 뽑아("자신을 '인사쟁이'로 소개하며 '상담쟁이' 역할을 하겠다고 선언") 스토리 구성이
  hook 으로 채택했다. **인사·자기소개는 인트로가 아니지만 본문도 아니다** — 후보 단계에서
  걸러낼 축이 없다.
- `d0` 의 생성 실행에서는 그 구간이 **후보로 아예 나오지 않았다**. 즉 이번 우열의 일부는
  구성 능력이 아니라 **후보 추출의 실행 간 편차**다 — 같은 소스라도 실행마다 후보 집합이 다르다.
