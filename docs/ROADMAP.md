# Roadmap — Phase 0 → 5

원칙: **루프를 먼저, 모델은 나중.** 싼 레버부터. 각 페이즈는 측정 가능한 완료 기준을 가진다.

---

## Phase 0 — 데이터 + 로깅 인프라 (플라이휠의 토대)

목표: `(원본, 사람이 고른 구간, 성과)` 라벨 데이터셋 v0와, 모든 결정을 남기는 로깅 골격.

- [ ] [DATA_SCHEMA.md](DATA_SCHEMA.md) 대로 데이터 저장소 구성(메타 DB + 객체스토리지)
- [ ] COLLECTOR: 시드 채널 → 풀영상↔클립 쌍 매칭 (유튜브 롱폼 + 예능부터)
- [ ] ALIGNER: 오디오 지문 + 자막으로 클립을 원본 타임라인에 정렬, `align_confidence` 산출
- [ ] PREPROCESS v0: ASR + 장면 전환 + (예능)편집자막 OCR + 오디오 이벤트
- [ ] DecisionLog 기록 골격
- **완료 기준:** 정렬 신뢰도 높은 `(원본, 사람 span, 조회수)` 쌍 **수백 개** 확보 + hold-out 세트 고정

## Phase 1 — 오프라인 평가자 + 벤치마크 하베스

목표: 발행 0번으로 매일 반복 가능한 측정 토대.

- [ ] BENCHMARK: recall@k / IoU / boundary_err / weighted recall 자동 채점
- [ ] EVALUATOR(L0): LLM-judge 루브릭(훅·자기완결성·payoff·감정아크 + 도메인 보너스)
- [ ] 리더보드 + Experiment 버전 추적
- **완료 기준:** 임의 파이프라인을 hold-out에서 자동 채점 → 리더보드 갱신까지 원클릭

## Phase 2 — 후보 생성 + 랭킹, 자기개선 L0/L1 가동

목표: AI가 후보를 만들고, 평가자로 랭킹하고, **스스로 프롬프트·파이프라인을 개선**.

- [ ] UNDERSTAND + GENERATOR: 멀티모달 후보 생성(경계 스냅 + 변형)
- [ ] EVALUATOR로 랭킹 → BENCHMARK로 측정
- [ ] IMPROVER(L0): 실패 영상 분석 → 선택 프롬프트/루브릭 자동 재작성(reflection)
- [ ] IMPROVER(L1): 파이프라인 구성 탐색(밴딧/유전) + champion–challenger 승급
- **완료 기준:** 자기개선 루프 1회전마다 hold-out recall이 **유의하게** 개선되는 곡선 확인

## Phase 3 — 보상모델 학습 (L2, 최고 레버리지)

목표: LLM-judge를 값싼 자체 프록시 보상모델로 distill·고도화. (하이브리드: 여기서 자체 학습 시작)

- [ ] `클립 멀티모달 피처 → 사람 선택확률/성과` 회귀·랭킹 모델 학습
- [ ] ground truth(조회수)로 보정, 보상 해킹 감시 지표 추가
- **완료 기준:** 프록시 보상모델 랭킹이 LLM-judge보다 싸고 벤치마크에서 동등 이상

## Phase 4 — (선택) 렌더링 + 소량 실발행 보정

목표: 실제 쇼츠 산출물 + ground truth로 프록시 보정. ※권리 확보 콘텐츠 한정.

- [ ] RENDER: 9:16 리프레임(얼굴 트래킹) · 자막 번인 · 필러/정적 제거 · 훅 카피
- [ ] 소량 발행 → Outcome 수집 → 보상모델 보정
- **완료 기준:** 실지표와 오프라인 프록시의 상관관계 확보

## Phase 5 — 정책 파인튜닝 (L3, 정체 시에만)

목표: 싼 레버가 정체될 때 전문 모델을 직접 학습.

- [ ] winner/loser 쌍으로 컷 선택·경계·훅 모델 SFT → DPO
- [ ] (선택) 보상모델 대상 RL
- **완료 기준:** 파인튜닝 모델이 API+프롬프트 최고 구성을 벤치마크에서 능가

## 지금 당장의 다음 한 걸음

**Phase 0의 COLLECTOR + ALIGNER**가 모든 것의 출발점이다.
정답 라벨(`원본 ↔ 사람 span ↔ 조회수`)이 생기는 순간, 나머지 전부가 측정 가능해진다.
