## TL;DR

편집 피처는 실제 성과(조회수)와 상관 ≈0이고, 유일하게 보이던 "작품 내 시청유지" 신호조차
**길이 정규화의 기계적 artifact**였다(길이를 빼면 0, 유의하지 않음). 한편 **ai-video 에는 이미
Gemini 기반 평가자(viral_score)가 들어 있다.** 따라서 self-improvement 의 핵심(평가자를 실제 성과로
보정·향상)은 관측만으로 불가능하며 **개입(intervention) 데이터**가 필요하다:
① **단일 채널 A/B**(인과·최선) ② **핑거프린팅**으로 같은-순간 다른-편집 비교(차선).
가장 싼 우회였던 ③ **VLM pairwise 프록시는 실행했으나 실패**(20쌍 중 17쌍이 순서 바꾸면 판정 뒤집힘 = 위치편향 지배, 실성과 예측 0/3 §6-C).

**→ ★돌파구(§9): 사용자가 지목한 ai-video 자기채널(재미쇼츠·스토리순삭)에 '같은 작품 시장 대비 벤치마크'를 돌리니 신호가 나왔다.** ai-video 클립은 같은 작품 시장 클립 대비 시청유지 **~20 백분위**(길이통제 후 21%) = 실재하는 craft 격차. **관측 천장(절대 예측)과 달리, 같은 소스에 대한 '상대 벤치마크'는 작동한다.** 이것이 자기개선의 첫 actionable 타깃이고, 검증은 같은 채널들의 A/B.

## 1. 무엇을, 어떻게 검증했나
- **타깃(성과 y)** 두 가지(+14일 확정):
  - `apv` = avg_view_pct = watch_time /(views × video_length). **시청유지·루핑** 지표. 쇼츠는 루프되어 1.0 초과 가능(중앙값 0.44, 최대 6.0).
  - `views` = **도달**(실제로 중요한 결과·수익과 직결).
- **통제(교란)**: 작품(work)·채널·길이. 질문은 항상 *"편집 피처가 컨텍스트 너머로 성과를 설명하나?"*
- **피처**: 결정론(컷수·샷길이·컷리듬·훅타이밍·전환·침묵/발화비) + 관찰형(화자수·갈등·펀치라인·질문훅·토픽전환·얼굴수 등). 모두 `det+obs-v1`, 562 shorts.

## 3. 왜 이런가 (메커니즘)
1. **도달(views)은 알고리즘/추천 운에 지배** — 클립 피처와 구조적으로 무관(작품내에서도 0.016).
2. **apv 는 길이로 정규화된 비율** → 짧을수록 기계적으로 상승. 편집 피처(샷길이↓·컷수·훅타이밍↓)는 길이와 collinear → 길이의 대리.
3. 절대회귀가 신호를 "놓친" 게 아님(트리가 작품 125개를 못 흡수한 건 맞지만) — 작품내로 정확히 들어가도 **길이 빼면 craft 신호 없음**.
4. 근본 원인: 관측 데이터엔 **"같은 순간을 다르게 편집한 대조군"이 없다.** 편집 craft 가 moment-selection·도달운과 완전히 교란되어 **식별 불가**.

## 5. ai-video 현황 — 이미 있는 것 (중요)
`/Users/gimsewon/rhoonart/ai-video` 조사 결과:
- **14단계 파이프라인**, 후보를 다수 생성: 청크당 moment 후보(20~50개) → **스토리라인 3~6개 생성**(`gemini_client.py:1647`) → Gemini 가 `viral_score`·`coherence_score` 채점 → `composite = viral*0.6 + coherence*0.4`(`:1755`) → 다양성 필터(`story_builder.py:65`) → 임계값 0.4 게이트 → **상위 1~3 발행**(`--max-shorts`).
- **즉 ai-video 에는 이미 LLM 평가자가 있다.** 단 **실제 성과로 보정된 적이 없다.**
- 탈락 후보는 선택 시점 메모리엔 있으나 **영구 로깅 안 됨**. 켜면 chosen-vs-rejected 쌍을 확보할 수 있으나 **Gemini 가 판정한 쌍 = 순환**(자기 증류). 실성과 라벨 없으면 평가자를 *향상*시키지 못하고 *모방*만 함.

→ self-improvement 의 부가가치는 명확하다: **실제 성과로 평가자를 보정**하는 것. 그런데 그 "실제 성과 ↔ 편집 선택" 라벨이 관측엔 없다(§2). = **개입 필요.**

## 6. 방향 — 3갈래 (자원 의존)
**A. 단일 채널 A/B (인과·최선).** ai-video 가 이미 top-2 후보를 만든다 → **1개만 발행하던 것을 2개 발행해 승부**시키고 +14일 성과로 승자 라벨. 이 승패가 평가자를 보정하는 **유일한 진짜 신호**이며, 누적되면 그 자체가 moat(경쟁자가 못 가진 A/B 선호 데이터셋). *필요: 발행 채널 + 운영 동의.* 진입장벽은 낮음(후보 생성은 이미 됨, top-2 발행 + 성과 수집만 추가).

**B. 핑거프린팅 → 같은-순간 다른-편집 (차선).** 보유 원본 롱폼에 기존 쇼츠를 오디오/영상 지문으로 매칭 → `origin` 구간 복원 → **같은 구간·다른 편집**끼리 retention 비교(길이 매칭 가능) + ai-video moment-selection **recall@k** 벤치. 관측이지만 moment-selection 교란을 제거. *필요: 원본 롱폼 라이브러리 접근.*

**C. VLM pairwise 프록시 보상 (가장 쌈) — 실행 완료, 실패(n=20).** 같은 작품 두 클립 중 "더 나은 편집"을 강제선택(양방향 A↔B 스왑 일관성).
- **결과: 20쌍 중 17쌍이 순서를 바꾸면 선택이 뒤집힘(위치편향 지배).** confidence 평균 **0.81**인데도 비일관 = 자신만만 오판. 일관 3쌍의 **views 랭킹 일치 0/3**, 길이매칭 0/1, apv 일치 1/3(모두 n.s.).
- **해석: Gemini 2.5 Pro 도 같은-작품 두 클립의 편집 우열을 신뢰성 있게 변별하지 못한다**(naive pairwise·force-choice). 원인은 §2~3 천장과 동일 — 두 클립의 차이가 VLM 이 지각할 만한 *craft* 차이가 아니라(apv 갭은 길이/운), 비슷한 둘을 강제선택시키니 위치편향으로 코인플립.
- **함의: SPEC §3 의 "VLM judge = moat" 가설에 강한 반증.** 사람 앵커 *보정* 이전에 *변별* 자체가 안 됨. (단, 큰 craft 차이가 있는 쌍·위치편향 완화·축별 판정 등 재설계 여지는 남음 — 그러나 그건 craft ground-truth 가 있어야 검증 가능 → 결국 A/B 로 회귀.) 스크립트: `scripts/m2_pairwise_judge.py`, `scripts/m2_analyze.py`.

ai-video 클립 vs 같은 작품 휴먼 apv 승자 강제비교(양방향). **다운로드 실패**(유미 휴먼승자·찬란한 ai-video 클립이 YouTube 불가)로 일관 판정 **2건뿐**(둘 다 휴먼 정답, 2/2 n.s.).
- **VLM 변별력: 성공 7건 중 5건이 순서 뒤집힘(None)** — *실제 품질 격차가 있어도* forced-pairwise 는 위치편향으로 불안정. → **VLM 을 pairwise '보상'으로 쓰지 말 것**(§6-C m2 와 일치).
- **단, 일관 시 reason 은 일관·예리**(의미축 '왜', 저n·가설): ai-video 클립은 ①**여러 장면을 산만하게 이어붙임**(휴먼은 단일 장면 완결) ②**페이오프/결말 없음**('예고편처럼', 갈등만 제기하고 해결 X) ③**설명 자막 없이는 이해 불가**.
- → **의미축 directive**: **단일 장면 완결성·명확한 페이오프(기승전결)·자막 의존 축소.** ai-video `story` 단계가 후보를 여러 개 '스토리라인'으로 엮는 구조(montage)가 산만함의 원인일 수 있음.
- **결론: VLM 은 '보상'이 아니라 '왜 생성기'로만 유효.**

### 9-4. 검증 — 오디오 실측 (2026-06-16, n=2 ai-video + 1 market, 로맨스의 절댓값)
'무음 49%'가 **컷 가능한 데드에어인가** vs 저음량 artifact인가 확인:
| clip | 길이 | 무음 gap | 무음% | mean vol | max vol | 통합 LUFS |
|---|---|---|---|---|---|---|
| ai-video iHAqMZBNQJA | 42s | **13개** | 34% | −36.3dB | −15.5dB | **−32.4** |
| ai-video oUgzkwvrzas | 43s | **21개** | 51% | −36.3dB | −17.2dB | **−32.0** |
| market 2K7eCKix2Ec | 53s | 4개 | 7% | −26.4dB | −9.8dB | **−22.8** |

- **① 데드에어 확정(컷 가능):** ai-video 는 0.5~2.7s짜리 무음 gap 이 13·21개 산재(market 4개) → 세그먼트 사이 죽은 시간. **silence_cut(gap-단위) 수정이 정확한 처방.**
- **② 라우드니스 격차(신규):** ai-video −32 LUFS vs market −23 LUFS (~9 LUFS 더 조용, peak도 −15/−17 vs −9.8). 쇼츠 표준 −14 대비 ai-video 는 매우 조용. **→ render 단계 loudnorm(=−14 LUFS) 추가 = 쉬운 고ROI 개선.** (데드에어와 별개 처방.)

**Caveat:** n=29(드라마 3작품 집중). '시장'에 타 자동화툴 포함 가능. ai-video 생성 메타(viral_score·후보)는 30일 만료로 과거분 소실 → 향후 durable 로깅 필요.

## 10. ②(관측 분석) 폐기 vs 계승 — 다시 관측-예측 길로 빠지지 않기
관측 천장(§2~3)은 "실패"가 아니라 **잘못된 접근 하나를 확정적으로 제거 + 진짜 길(벤치마크)을 가리킨** 단계. 버릴 것과 계승할 것을 못박는다.

**🗑 버릴 것 (다시 안 감):**
| 버리는 것 | 왜 |
|---|---|
| 관측 피처 → 성과 리워드 모델(결정론·관찰·의미 회귀) | +14일 성과에 신호 0(천장). 더 하면 노이즈 최적화 |
| VLM forced-pairwise 를 '보상/점수'로 | 실격차 있어도 17/20 순서뒤집힘(위치편향) → 보상 부적합 |
| raw `avg_view_pct` 를 craft 신호로 직해석 | 길이정규화 artifact. 길이 통제 없이 불신 |
| "피처 더 뽑으면 예측된다" 가설 | 천장 → 피처 추출에 추가 투자 X |
| VLM 절대 점수(판단형 채점) | 포화. 관찰형으로 바꿔도 예측 천장 |

**✅ 계승할 것 (③ 이후로 넘어감):**
| 계승 | 재사용처 |
|---|---|
| 데이터 토대(M0): 격리 DB·ETL·60k·+14일 | ③ 벤치마크 + A/B(`clip_performance` 조인) |
| 작품내 비교 방법론(`m1_within_work_pairs`, 작품 고정효과 차분) | ③ 벤치마크 + `m4_ab_analysis`(소스 페어링) 핵심 엔진 |
| 교란 통제 사고(작품·채널·길이 정규화/잔차) | ③ "같은 작품 비교" 로직 |
| "관측 천장 → 개입/참조 필요" 인사이트 | 전체 방향타(벤치마크·A/B) |
| VLM = '왜 생성기'(점수 X, 이유 O) | ④ 원인규명 정성 단서 |
| 엔지니어링 교훈 | CV누수(`DISTINCT ON`)·길이교란·쿠키다운로드·per-clip 타임아웃 |

**한 줄:** ②에서 버린 건 "관측만으로 성과 예측" 접근 **하나뿐**, 데이터·방법론·인사이트·교훈은 전부 계승되어 현 벤치마크·A/B를 떠받침. (그래서 빨강 아님, 주황=전환점.)
