# Evaluation — 보상 아키텍처와 벤치마크

> 자기개선은 측정 가능한 목적함수가 없으면 말장난이다.
> 우리의 1차 목적함수는 **"사람이 고른 구간을 얼마나 맞히나(오프라인 recall)"** 이다.

## 보상 3층 (느림 ↔ 빠름)

| 층 | 정의 | 속도 | 역할 |
|---|---|---|---|
| **Ground truth** | 실제 플랫폼 지표(조회수·유지율·공유) + 사람이 클립으로 뽑았다는 사실 | 느림·희소 | 북극성. 프록시 보정용 |
| **Proxy 보상모델** | `클립 피처 → 성과/선택확률` 예측 모델(L2) | 빠름·조밀 | 발행 없이 수천 후보 점수화 |
| **휴리스틱/루브릭** | LLM-judge 루브릭 + 객관 신호 | 즉시·저렴 | 콜드스타트, 빠른 반복 |

전략: **느린 ground truth로 빠른 프록시를 보정**하고, 평소엔 프록시로 100배 빠르게 반복한다.

## 1차 메트릭 — 오프라인 벤치마크 (Phase 1의 핵심 산출)

원본을 주고 AI가 고른 후보가, **성공한 사람 클리퍼가 고른 구간**과 얼마나 겹치나.

| 메트릭 | 정의 | 의미 |
|---|---|---|
| **recall@k** | AI 상위 k개 후보가 사람 클립 구간을 덮는 비율 | "놓치지 않는가"(발굴력) |
| **IoU** | 후보 구간 ∩ 사람 구간 / ∪ | 경계가 얼마나 정확한가 |
| **boundary_err** | in/out 타임코드 절대 오차(초) | 컷 정밀도 |
| **precision@k** | 상위 k 중 실제 사람 클립과 매칭된 비율 | "헛것을 고르지 않는가"(taste) |
| **weighted recall** | 조회수로 가중한 recall | "뜬 클립"을 우선 맞히는가 |

발행 0번으로 매일 수백 번 돌릴 수 있는 게 핵심. 모든 Experiment는 동일한 hold-out 원본 세트에서 채점하고 리더보드에 올린다.

## 클립 ↔ 원본 자동 정렬 (정답 라벨 생성)

사람 클립은 원본의 일부 구간이다. 어느 `[start,end]`인지 자동 복원한다:

1. **오디오 지문(audio fingerprint)** — 클립의 오디오 지문을 원본에서 검색해 시작점 정렬. (chromaprint류)
2. **자막/ASR 매칭** — 클립 대사를 원본 ASR 타임라인에 정렬(보조·검증).
3. **신뢰도 산출** — 두 방법 일치도로 `align_confidence`. 낮으면 벤치마크에서 제외.

이 정렬이 곧 `HumanClip.aligned_start_s/end_s` → recall의 정답이 된다.

## 2차 메트릭 — LLM-judge 루브릭 (즉시 보상)

발행 전, 후보 자체의 품질을 0~1로 채점:

- **훅 강도** — 첫 1~3초가 스크롤을 멈추는가
- **자기완결성** — 앞뒤 맥락 없이 이해되는가
- **payoff** — 긴장→해소/펀치라인이 있는가
- **감정 아크** — 기복(변동성)이 있는가
- **도메인 보너스** — 예능: 편집자막/웃음 정렬 / 드라마: BGM 고조·클로즈업 정렬

루브릭 점수는 처음엔 LLM-judge로, 데이터가 쌓이면 프록시 보상모델(L2)로 distill.

## 3차 메트릭 — 실발행 지표 (Phase 4+, 선택)

| 지표 | 의미 |
|---|---|
| `swipe_away_3s` | 훅 품질(가장 중요) |
| `avg_watch_pct` | 유지율의 왕 |
| `shares` / `saves` | 가장 강한 바이럴 신호 |
| `follows` per view | 채널 가치 |

⚠️ 소표본 노이즈에 과적합 금지. 실지표는 **프록시 보정용**으로 쓰고, 일상 반복은 오프라인 벤치마크로.

## 회귀 방지 · 거버넌스

- hold-out 원본 세트는 고정(데이터 누수 방지). 주기적으로만 교체.
- champion–challenger: 새 Experiment가 hold-out에서 챔피언을 **유의하게** 이겨야 승급.
- **보상 해킹 감시**: 프록시는 오르는데 ground truth가 안 오르면 경보 → 평가자 재점검.
