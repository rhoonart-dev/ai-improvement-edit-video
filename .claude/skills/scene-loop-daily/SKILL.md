# scene_loop 결과 보고 (생성은 launchd 담당)

**이 스킬은 생성을 띄우지 않는다. 로그를 읽고 보고만 한다.**

## 표준 구성 (2026-07-31~, 전 머신 동일)

생성과 보고를 분리한다.

| | 담당 | 시각 |
|---|---|---|
| 생성 | launchd `com.rhoonart.scene-loop` → `scripts/scene_loop_run.sh` | 매일 04:00 |
| 보고 | 이 스킬 (예약 작업) | 매일 10:00 |

러너가 배정 검증 게이트·중복 실행 락·PATH 보정·로깅을 전부 자체 처리한다. 설치는
`./scripts/install_scene_loop_launchd.sh`, 자세한 건 `SCENE_LOOP_OPERATIONS.md §5`.

**왜 분리했나**: 예전에는 이 예약 세션이 생성까지 띄웠는데, 세션이 승인창에서 멈추면 그날
생성이 통째로 유실됐다(7/28·7/29). 이제 이 세션이 죽어도 손실은 "보고 하루 누락"뿐이다.
**그러니 세션을 살리자고 생성을 대신 띄우지 말 것** — 그게 이 구성의 요점이다.

> ★ **담당 채널을 이 문서에 적지 않는다.** 배정 정본은 `config/assignments.json` 이고 루프가
> 스스로 이 머신의 담당분을 찾는다. 예전에는 프롬프트 마지막 줄에 채널명을 손으로 적었는데,
> 그 손편집이 머신마다 배정이 어긋나는 원인이었다.

## 절차

1) 지난밤 생성 로그를 읽는다

```bash
tail -80 ~/ves/ai-improvement-edit-video/results/scene_loop.log
```

2) 로그에 지난밤 항목이 **아예 없을 때만**, launchd 가 러너를 시작조차 못했는지 본다

```bash
tail -20 ~/ves/ai-improvement-edit-video/results/launchd_scene_loop.err
launchctl print gui/$(id -u)/com.rhoonart.scene-loop | grep -E "state =|runs =|last exit"
```

3) 상태를 판정해 보고한다. 로그에서 찾을 표지:

| 로그 | 뜻 | 보고 |
|---|---|---|
| `scene_loop 시작` → `종료 (rc=0)` | 정상 완료 | 채널별 생성 장면 요약 |
| `⛔ 검증 실패 → 생성하지 않고 종료` | 배정/작품 카드 문제 | **사람이 할 일** 로 올린다 |
| `이미 실행 중(pid=…) → 이번 회차 건너뜀` | 이전 실행이 아직 진행 중 | 정상. 겹침 방지가 작동한 것 |
| `stale 락 회수` | 이전 실행이 비정상 종료했었음 | 함께 보고 |
| `종료 (rc=2)` 또는 rc≠0 | 실패 | 사유만 보고 |
| 시작은 있는데 종료가 없음 | 아직 생성 중 | "진행 중" 으로 보고하고 끝낸다 |
| 지난밤 항목 자체가 없음 | launchd 미발화 | 2)의 결과와 함께 보고 |

⛔ **기다리지 말 것 — `sleep`·`until` 대기·Monitor 를 쓰지 않는다.** 채널이 많은 머신
(luna1~4 는 4채널)은 10:00 에도 아직 돌고 있을 수 있다. 그때는 거기까지의 결과를 보고하면
된다. 완료를 기다리는 건 이 세션의 일이 아니다.

## 보고 형식 (짧게)

- 지난밤 생성 결과 — 채널별 EP·생성된 장면·rc
- 현재 상태 — 완료인지 진행 중인지
- **사람이 할 일** — 미공개 대기로 멈춘 채널, 검증 ⛔, 소스 없어 대기 중인 회차, launchd 미발화

## 주의

- **생성을 직접 띄우지 않는다.** 실패했어도 재시도하지 않는다 — 사유만 보고한다(생성 비용·Gemini 지출 한도).
- `config/assignments.json`·`works.json`·`results/scene_loop_state.json` 을 임의로 고치지 않는다.
- 생성 결과가 이상해도(인물명 오류 등) 스스로 판단해 재생성하지 않는다 — 보고하고 사람이 정한다.
- launchd 잡을 이 세션에서 수정·삭제하지 않는다. 문제가 있으면 보고한다.
